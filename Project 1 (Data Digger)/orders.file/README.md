# 📌 Overview

The **Orders.sql** module is the second core component of the **DataDigger Database Management System**.

This module is responsible for storing customer order information and establishing a relationship between customers and their orders using **Primary Key** and **Foreign Key** constraints.

The Orders table keeps track of order details such as the customer who placed the order, the order date, and the total order amount. It demonstrates how relational databases maintain data consistency while performing CRUD operations and analytical SQL queries.

---

# 🎯 Problem Statement

> **Objective:** Design and implement an Orders table that stores customer order information and maintains relationships using Foreign Keys.

The system should allow users to:

- Store order information securely.
- Link every order to an existing customer.
- Retrieve customer orders.
- Update order information.
- Delete unnecessary orders.
- Generate order reports using SQL Aggregate Functions.
- Retrieve recent orders efficiently.

This module introduces relational database concepts using **Foreign Key relationships** and practical SQL queries.

# 📦 Orders Table Structure

The **Orders** table stores all order-related information generated by customers.

Each order belongs to one customer, which is achieved using a **Foreign Key** relationship.

---

## 📋 Table Design

| Column Name | Data Type | Constraint | Description |
|-------------|-----------|------------|-------------|
| `OrderID` | INT | PRIMARY KEY | Unique Order Identifier |
| `cust_id` | INT | FOREIGN KEY | References Customers Table |
| `OrderDate` | DATE | NOT NULL | Date on which the order was placed |
| `TotalAmount` | INT | NOT NULL | Total amount of the order |

---

# 🔑 Primary Key

```sql
OrderID INT PRIMARY KEY
```

### Why Primary Key?

- Assigns a unique identity to every order.
- Prevents duplicate Order IDs.
- Makes record searching faster.
- Ensures every order is uniquely identifiable.

---

# 🔗 Foreign Key

```sql
FOREIGN KEY (cust_id)
REFERENCES Customers(cust_id)
```

### Why Foreign Key?

- Connects every order with an existing customer.
- Prevents invalid customer references.
- Maintains data consistency.
- Establishes a relationship between Customers and Orders tables.

## 1️⃣ Create Orders Table

Creates the Orders table with Primary Key and Foreign Key constraints.

```sql
CREATE TABLE Orders(
OrderID INT PRIMARY KEY,
cust_id INT,
OrderDate DATE,
TotalAmount INT,
FOREIGN KEY(cust_id)
REFERENCES Customers(cust_id)
);
```

---

## 2️⃣ Insert Sample Order Records

Stores order information inside the database.

Example:

```sql
INSERT INTO Orders
VALUES
(1,1,'2026-08-01',2500);
```

Multiple records can be inserted to simulate customer orders.

---

## 3️⃣ Retrieve Order Records

Displays all orders stored in the database.

Example:

```sql
SELECT * FROM Orders;
```

Useful for viewing complete order information.

---

## 4️⃣ Retrieve Orders of a Specific Customer

Displays orders placed by a particular customer.

Example:

```sql
SELECT *
FROM Orders
WHERE cust_id=2;
```

Only orders belonging to the selected customer are displayed.

---

## 5️⃣ Update Order Amount

Updates the total amount of an existing order.

Example:

```sql
UPDATE Orders
SET TotalAmount=3000
WHERE OrderID=1;
```

Only the selected order is modified.

---

## 6️⃣ Delete an Order

Deletes an order using its unique **Order ID**.

### SQL Query

```sql
DELETE FROM Orders
WHERE OrderID = 2;
```

### 📖 Explanation

- Removes a specific order from the Orders table.
- Uses the **Primary Key (OrderID)** to identify the correct record.
- Prevents accidental deletion of multiple orders.

---

## 7️⃣ Retrieve Orders Placed in the Last 30 Days

Displays all orders placed within the last 30 days.

### SQL Query

```sql
SELECT *
FROM Orders
WHERE OrderDate >= CURDATE() - INTERVAL 30 DAY;
```

### 📖 Explanation

- `CURDATE()` returns the current system date.
- `INTERVAL 30 DAY` subtracts 30 days from today's date.
- Retrieves only the recent orders.

---

## 8️⃣ Find the Highest Order Amount

Displays the highest order amount.

### SQL Query

```sql
SELECT MAX(TotalAmount)
FROM Orders;
```

### 📖 Explanation

- Uses the **MAX()** aggregate function.
- Returns the maximum value from the `TotalAmount` column.

---

## 9️⃣ Find the Lowest Order Amount

Displays the smallest order amount.

### SQL Query

```sql
SELECT MIN(TotalAmount)
FROM Orders;
```

### 📖 Explanation

- Uses the **MIN()** aggregate function.
- Returns the minimum order amount stored in the table.

---

## 🔟 Find the Average Order Amount

Calculates the average value of all orders.

### SQL Query

```sql
SELECT AVG(TotalAmount)
FROM Orders;
```

### 📖 Explanation

- Uses the **AVG()** aggregate function.
- Calculates the average order amount.
